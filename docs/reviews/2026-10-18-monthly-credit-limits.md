# Monthly credit limits

October 18, 2026. Each quota bucket can now show its provider-returned monthly credit limit and spend-control state inside Reading details. The main quota view stays unchanged. Missing values show Not supplied. Zero stays zero, and a false spend-control flag shows Not reached.

Rust preserves the monthly limit as an exact provider string. The UI preserves spaces and trailing zeros, with no numeric conversion or currency inference. A labeled keyboard-scrollable value uses the existing quota viewport. Spend-control state remains independent of monthly limits, reset credits, account balance, and ordinary usage permission. No spending control, schema, history writer, or accepted identity is added.

The pinned [official protocol](https://github.com/openai/codex/blob/83086188ae0614bd882818ff1aa23f3194962012/codex-rs/app-server-protocol/src/protocol/v2/account.rs#L664-L677) returns the two optional fields separately. Its [monthly-limit structure](https://github.com/openai/codex/blob/83086188ae0614bd882818ff1aa23f3194962012/codex-rs/app-server-protocol/src/protocol/v2/account.rs#L792-L798) uses a string. The [official status view](https://github.com/openai/codex/blob/83086188ae0614bd882818ff1aa23f3194962012/codex-rs/tui/src/status/rate_limits.rs#L114-L137) identifies the effective monthly limit. A [backend test](https://github.com/openai/codex/blob/83086188ae0614bd882818ff1aa23f3194962012/codex-rs/backend-client/src/client.rs#L1004-L1023) confirms that spend-control state can exist without that limit.
