# Sign-in page and wait limit

October 18, 2026. An active device sign-in now offers Open sign-in page beside the existing address, code, and Cancel action. The click requests the system's default browser. A launch error keeps manual copy and retry available. The app does not claim that a browser page loaded or sign-in succeeded.

The renderer sends only the selected profile and attempt IDs. Rust requires an unlocked workspace, a current published prompt, and matching profile, home, revision, approval, and generation. It then passes one fixed public OpenAI address to the operating system. No code, provider login identifier, token, credential, key, arbitrary URL, path, or program enters that request. No general opener plugin or renderer permission is registered.

The pinned open 5.4.4 library supplies the same dispatch used by [Tauri's standalone opener](https://docs.rs/tauri-plugin-opener/2.7.2/src/tauri_plugin_opener/open.rs.html#9-14). It adds three MIT packages without changing existing package versions. This avoids unused plugin and asynchronous-runtime dependencies. [The library documents](https://docs.rs/open/5.4.4/open/fn.that_detached.html) a native handoff. It does not establish that the browser loaded the page.

The dedicated native journey used a private HTTPS association and synthetic local handler. A real UI click dispatched exactly the fixed address. Missing-launcher failure, same-attempt retry, malformed and stale requests, cancellation, owned-process cleanup, and unchanged encrypted records passed. No Windows or system browser launcher was available in its private search path. No real browser or network request occurred.

The full sign-in regression retained all eighteen cases. Eight reviewed captures cover both themes, narrow windows, selectable fields, and enlarged text. An added 200% capture shows both new browser and Cancel labels at 28 pixels, inside a 360-pixel window. Actual Tab gave the browser button a visible outline. Both inverse text-scale restorations passed. Three-operation strict cancellation and the ordinary privacy-button regression passed separately. The default production executable refused all three synthetic providers.

A separate native journey exercised the unchanged full 900-second wait. The app reported timeout after 900.474 seconds from consent submission and 900.346 seconds from the observed prompt. The real completion promise lasted 900.062 seconds. The prompt cleared, focus reached the error, the owned process and group were reaped, and a fresh attempt reused the slot before cancellation. Database, WAL, wrapped key, and all synthetic homes stayed unchanged. This proves the application wait limit, not provider-code expiry.

Two test faults were corrected without changing production behavior. Tauri freezes its exported API namespace, so an observer assignment did nothing. The corrected test uses a checked forwarding namespace and returns each original promise unchanged. A deliberate home rename also correctly caused cleanup failure. Its test now requires that exact error, preserved original and replacement homes, and process reaping. Cleanup errors remain visible.

Fresh Rust checks passed 123 tests, strict Clippy, and formatting. One owned child helper remains intentionally ignored. The frontend check passed 24 contracts and 18 renderer journeys. The combined audit (private evidence omitted) binds five journeys and 22 final captures. It preserves the original failures and the earlier seven-frame sign-in receipt.

The full timeout ran on the earlier `741f8c0` executable; it did not run again on the browser executable. Its core timer and session source remain unchanged. Every receipt retains that exact source and artifact scope.
