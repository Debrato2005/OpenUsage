# Build and test artifact policy

Git commits preserve source history. Small verification receipts record the producing commit, dirty-source status, lockfile hashes, toolchain, build command, test result and artifact hash. A receipt with missing provenance is incomplete. A passing old binary does not qualify a new build.

- Normal verification uses the current build output. `scripts/freeze-native-artifact.py SOURCE LABEL` writes a receipt only. Supply `--source-workspace`, `--build-command` and `--test-reference` to bind its provenance. The recovery helper delegates to this maintained script.
- Retaining executable bytes requires explicit `--retain` for current debugging, release qualification or security evidence. At most four desktop/owned executable copies and 1.5 GiB may remain; the helper refuses additional retention at the cap. Official companions and required read-only test oracles are separate dependencies. Remove a retired copy only after preserving its receipt and confirming that it is not active, the only source recovery copy or irreplaceable evidence.
- Use one shared Cargo target directory and one dependency installation. Do not copy target or node_modules directories into agent worktrees. Development/test profiles disable incremental caches and retain line-level debug information. Full debugger type information can be enabled for a specific investigation with the standard Cargo profile environment overrides.
- After integrating an agent slice, commit it, check for unique/untracked/ignored data, preserve detached commits with a local ref, then remove the clean worktree with `git worktree remove PATH`. Never use force to discard unique work. Keep one physical copy of required test evidence rather than duplicating it into each checkout.
- Keep screenshots for changed workflows and essential acceptance results. Keep concise results linked to commits; do not recopy entire previous evidence trees. Temporary workspaces and partial outputs must be removed in the runner's final cleanup.
- CI uses temporary build outputs. Any explicitly uploaded debug/release-candidate binary expires within seven days; routine receipts expire within fourteen days unless selected as essential acceptance evidence. Final releases and non-reproducible security evidence use an explicit retention exception. Never upload credentials, user databases, keys or private backups.
- Run relevant acceptance tests against each current build. Clean disposable outputs after the milestone; do not immediately rebuild merely to prove a cache can be regenerated.

These rules apply on Windows, macOS and Linux through Git and the platform's build tools. The current recovery freeze helper is for the Linux/WSL build workflow; it does not establish Windows/macOS build acceptance. No remote publication is permitted by this policy.

The October 21 cleanup retired obsolete desktop binaries, duplicate installer/package staging, redundant Git bundles and 94 clean worktrees. Their commits remain in local Git; required database/backup evidence remains in the canonical checkout. Dirty worktrees and current/rollback binaries were preserved. Exact local measurements are in `.recovery/audit/p0-*.json`.
